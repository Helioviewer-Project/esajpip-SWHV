# ACN v2: a determinant passed to SEQUENCE OF elements is not deferred

asn1scc 4.9.3.0 (161cc2465b568685c09b0a218149fb514ea2a95e), C backend,
`--acn-v2`.

## Summary

With `--acn-v2`, an ACN inserted field of a SEQUENCE that is passed as an
argument to a child of a reference type is a deferred determinant: the
SEQUENCE's encoder reserves its bits (`Acn_InitDet_*`), the child's encoder
patches them (`Acn_PatchDet_*`), and the decoder decodes it into the
`AcnInsertedFieldRef` it passes down. A SEQUENCE OF child hides the
reference type of its elements from the deferred-determinant collector:

`items [size count] { <len> [] }` passes `len` to each element. The
SEQUENCE does not treat `len` as deferred. Its encoder computes `len` the
ordinary way, from an element's size, but outside the element loop, so it
reads `pVal->items.arr[i1]` with `i1` uninitialized:

```c
int i1;
...
Msg_len_is_initialized = TRUE;
Msg_len = pVal->items.arr[i1].data.nCount;
```

It then writes `len` directly, while each element encoder still calls
`Acn_PatchDet_U8` on an `AcnInsertedFieldRef` that no `InitDet` set up
(position 0 of the stream). With optimization gcc reports
`'i1' may be used uninitialized`; at run time the read can crash or
produce a wrong determinant. A list that may be empty has no element to
take `len` from at all.

The separate [sibling-consumer failure](../0003-deferred-sibling-consumers/)
combines with this one in the JPEG 2000 Reader Requirements box (test 018).

## Reproducer

`min.asn1` / `min.acn`:

```asn1
Min DEFINITIONS AUTOMATIC TAGS ::= BEGIN
    Item ::= SEQUENCE { data OCTET STRING (SIZE (1..4)) }
    Msg ::= SEQUENCE { items SEQUENCE (SIZE (0..4)) OF Item }
END
```

```
Min DEFINITIONS ::= BEGIN
    Item <INTEGER:len> [] { data [size len] }
    Msg [] {
        len INTEGER [encoding pos-int, size 8],
        count INTEGER [encoding pos-int, size 8],
        items [size count] { <len> [] }
    }
END
```

`repro.c` encodes and decodes a `Msg` with two 2-byte items. `run.sh`
generates it, builds with ASan and UBSan, and runs it:

```sh
ASN1SCC="dotnet /path/to/asn1scc.dll" sh run.sh
```

Output with 4.9.3.0 (gcc 11.4, `-O0`):

```
==36==ERROR: AddressSanitizer: SEGV on unknown address 0x20104d0dc611 ...
SUMMARY: AddressSanitizer: SEGV .../min/min.c:135 in Msg_ACN_Encode
```

With patch `0002`:

```
encode ok=1: 02 02 A0 A0 A1 A1
decode ok=1
```

## Cause

`BackendAst/DAstACNDeferred.fs`:

`collectDeferredDetNames` and `collectDeferredDetNamesFromAst` collect
arguments of the SEQUENCE's children that are reference types
(`ReferenceType rt -> rt.acnArguments`) and ignore every other kind.
A SEQUENCE OF child passes its element type's arguments, so its determinants
are not collected. `createDeferredSequenceFunction` then keeps the ordinary
update statement whose access path ends in `arr[i1]`. The SEQUENCE OF code
already passes the `AcnInsertedFieldRef` to each element, which patches it.

## Fix

[`0002-deferred-sequence-of-arguments.patch`](../../asn1scc-patches/0002-deferred-sequence-of-arguments.patch)
makes both collectors look through SEQUENCE OF children, nested ones
included, to the element's reference type. `len` is then deferred:
`InitDet` before the list, `PatchDet` in each element, and the existing
fallback when no element patched it (0 for an empty list).

Upstream test `25-ACNV2-BOUNDARIES/016` and its wire test check the exact
bytes, a round trip, an empty list, and rejection of inconsistent element
sizes. It is `NO_AUTOMATIC_TEST_CASES` because automatic values can give
different element sizes that one determinant cannot encode.

Generated code after the fix, `min`:

```c
/*Encode Msg_len */
Acn_InitDet_U8(pBitStrm, &len);
...
for(i1=0; (i1 < (int)pVal->items.nCount) && ret; i1++)
{
    ret = Msg_items_elm_ACN_Encode((&(pVal->items.arr[i1])), pBitStrm, pErrCode, FALSE, &len);
}
if (ret) {
    if (!len.is_set) {
        Acn_PatchDet_U8((asn1SccUint)0, pBitStrm, &len, pErrCode);
    }
}
```

## Verification in the initial investigation

An initial check rebuilt `BackendAst.dll` against the other pinned 4.9.3.0
assemblies. Before patch `0002`, generated case `016` fails its `-Werror`
build with `'i1' may be used uninitialized`; afterward, its byte-exact
wire test passes. The regression's existing ACN cases and esajpip's model
generated byte-identical output in that check. The new case is `C_ONLY`.

## Revalidation against the pinned source (2026-09-26)

The complete pinned compiler was then built without patches and with the
first two patches. With GCC 13.3.0, the unpatched `min` encoder emits
`02 02 A0 A0 A1 A1`, but its decoder returns false; with patches `0001`
and `0002`, it round-trips. The AddressSanitizer crash quoted above was
recorded with GCC 11.4.0 and was not repeatable on GCC 13.3.0. The full
patched build passes `25-ACNV2-BOUNDARIES`, `runWireTests.sh`, and
`spec/check-model.sh`.
